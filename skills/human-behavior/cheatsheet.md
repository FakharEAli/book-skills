# Cheatsheet — decision rules, trees, thresholds, tells

## 1. Decision rules (When X → do Y, because Z)
- **Prospect said yes, no action in 5+ days** → send one message with one concrete channel (day/time/artifact), not a "checking in"; intentions without channels decay (02).
- **No reply from a busy owner** → assume tunneling, not rejection; re-enter with their current fire in their words (08).
- **Adoption is low** → check Prompt, then Ability, then Motivation, in that order; never start with training or incentives (07, 03).
- **Choosing between more features and fewer steps** → fewer steps, always; friction beats motivation for everyone (03, 04).
- **Client's old process persists after launch** → remove its cue and add friction to it; habits are insensitive to outcome (03, 07).
- **Objection sounds moral ("not right", "family business", "human touch")** → identify the foundation and answer on it; never counter with ROI (05).
- **A staff member stalls without saying why** → assume status threat; give them authorship before access (06).
- **Owner asks "how will this look to clients/competitors?"** → the real spec is visibility; make the first deliverable the visible one (10).
- **Choosing which proof to show** → same trade + same size + same region first; bigger logos second (09).
- **You feel like calling a client "flaky"** → write the situational explanation first; you are probably wrong about the cause (02, 01).
- **A curt or hostile email arrives** → read it as load, not character; reply short, one number, propose a time (01, 08).
- **Designing a pricing page** → one pre-selected recommended tier with outcome language; opt-outs visible (04).
- **Designing onboarding** → zero account creation, everything pre-filled, one approval, weekly feedback message (04, 07).
- **Launching a new workflow for a team** → group launch, team name, first-week numbers shared (05, 06).
- **Client wants to automate a step you don't understand** → ask what it protects before removing it (09).
- **Your own outreach is inconsistent** → treat it as a habit-design problem: anchor, tiny version, tally (07, 03).

## 2. Decision trees

**"They agreed but nothing happened" — which lever?**
- Did they know exactly what to do, when, where? No → **channel factor** (02): book it.
- Yes, but it required >1 step or a new tool → **ability/friction** (07, 03): cut steps.
- Yes, easy, but nothing reminded them at the right moment → **prompt** (07): attach to an existing action.
- Yes, easy, prompted, still nothing → is something urgent eating them? Yes → **tunneling** (08): wait or enter the tunnel.
- Nothing urgent → does saying yes cost someone status? Yes → **social pain** (06): defuse with authorship.
- No → **construal/moral** (02, 05): what does it mean about them? Reframe.

**Moral-objection map (05)**
| You hear | Foundation | Answer on it with |
|---|---|---|
| "We like the human touch", "our customers deserve a person" | Sanctity | reverence for the relationship; automation removes what keeps staff *away* from customers |
| "We look after our people", "family business" | Loyalty | staff keep their roles and gain authorship; nothing changes without their approval |
| "I don't want to depend on a system / on you" | Liberty | exit path, data ownership, off-switch shown up front |
| "That's my call", "I decide what goes to clients" | Authority | owner approves every template; system "prepares", never "decides" |
| "Is that fair for what we get?" | Fairness (proportionality) | value per hour/enquiry, not total price vs competitor |
| "Will it upset customers?" | Care | failure modes shown, human fallback explicit |

**"What is really being bought?" (motive triage, 10 + 09 + 08)**
- Questions about visibility, competitors, PR → **signal of modernity**: deliver a visible layer first.
- Questions about staff reactions, "who does what" → **status protection**: design status-safe framings.
- Questions about hours, "just make it stop" → **slack**: deliver the tunnel fix first, show hours back.
- Questions about "what do others like us do" → **conformity/prestige**: lead with self-similar proof.

**Which proof format?**
| Prospect is... | Lead with | Because |
|---|---|---|
| In a tight peer network (trade body, local) | Named prestigious peer's write-up | prestige + conformity bias (09) |
| Isolated / unusual niche | Self-similar case + your own CRED (live demo of your tools) | self-similarity + costly signal (09, 10) |
| Established, understated | Plain numbers, no AI jargon | counter-signaling (10) |
| New, growth-hungry | Visible sophistication, competitor comparison | signaling need (10) |

## 3. Trade-off matrices

**Driving force vs restraining force (02, 03)**
| Add push (discount, deadline) | Remove restraint (effort, fear, dependence) |
|---|---|
| Raises tension; works only if restraint is low | Lowers tension; works even when motivation is modest |
| Default: don't, until restraints are cleared | Default: do first |

**Nudge vs habit tool (04 vs 03/07)**
| One-off or rare decision (sign, choose tier, approve policy) | Repeated behavior (daily approvals, logging) |
|---|---|
| Defaults, structured choice, mappings (04) | Cue, friction, anchor, celebration, repetition (03, 07) |

**Visible vs invisible value (10, 06)**
| Deliver first | Deliver second |
|---|---|
| What the owner's audience can see | Deep back-office savings |

## 4. Choice-architecture defaults & thresholds the authors commit to
- First new behavior: **≤30 seconds** (07).
- Habit formation horizon: **median ~66 days, range 18–254**; plan check-ins at days 3, 14, 45 (03).
- Share of daily behavior that is habitual: **~43%**; design for it (03).
- Trait–behavior correlation ceiling in classic data: **~0.30**; don't predict from personality (02).
- Reward latency for habit training: **immediate**; weekly reports inform, they don't train (03).
- Asks per message to a scarce owner: **1** (08).
- Pricing tiers: **3, one pre-selected**, described by outcome (04).
- Account-creation steps before the client sees value: **0** (04).
- Troubleshooting order: **Prompt → Ability → Motivation** (07).
- Untangling order: **remove prompt → add friction → reduce motivation** (07).
- Nudge test: **would you explain it to the client without embarrassment?** If not, don't (04).

## 5. Tells & smells (if you see X, you're probably in Y)
- Enthusiastic call, then silence → tunneling or missing channel, not a change of mind (08, 02).
- "Send me more info" → no channel and a bandwidth tax; reply with a time slot, not a PDF (08, 02).
- "Let me run it past the team" → status map needed; someone loses face (06).
- "We like the human touch" → Sanctity foundation; answer with reverence (05).
- "I don't want to depend on a system" → Liberty foundation; show exit path and control (05).
- "Is it fair for the price?" → proportionality, not equality; show per-hour or per-enquiry value (05).
- Asks how to describe it publicly → signaling buyer; build the visible layer (10).
- Uses "cutting-edge" unprompted → wants a sophistication signal; mirror it, carefully (10).
- Understated, long-established, dismissive of hype → counter-signaler; strip jargon (10).
- Staff "haven't had time" for 3 weeks → social pain, not time (06).
- Old spreadsheet still open next to the new tool → cue not removed (03, 07).
- Usage spikes then dies by week 2 → motivation wave ended; design was not tiny enough (07).
- Owner replies only late at night → bandwidth-taxed; shorten everything, propose a daytime slot (08, 01).
- Curt, hostile one-liners → stress load; don't negotiate against it, re-approach at a calmer time (01).
- Peer's name comes up repeatedly → prestige node identified; go win them (09).
- Odd mandatory step everyone defends but can't explain → causal opacity; don't automate it away yet (09).
